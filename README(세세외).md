# 세입세출외현금 입출금 내역–근거자료 대조 도구 개발 요청

이 문서는 `정누리_나의_업무문제_정의서_작성본.docx`의 **첫 과제**를 구현할 AI에게 전달할 요구사항이다. 먼저 작은 로컬 시제품을 만들고, 실제 기관 시스템과 연동하거나 업무상 판단을 자동화하지 않는다.

## 1. 배경과 해결할 문제

- 사용자는 국군의무사령부 재정과에서 군인복지기금·세입세출외현금·국가채권을 담당하는 주무관이다.
- 세입세출외현금 입출금은 거의 매일 발생한다. 업무시스템의 거래 기록을 엑셀, PDF, 공문 등 다양한 근거자료와 건별로 대조한다.
- 특히 시스템에는 거래가 있지만 대응하는 근거자료가 없거나 식별정보가 불명확하면, 관련 자료와 담당자를 추적하는 데 경우에 따라 몇 시간이 걸린다. **없는 근거를 AI가 알아내거나 생성할 수는 없다.**
- 첫 과제의 목적은 실제 거래를 자동 처리하는 것이 아니라, 제공된 거래 목록과 근거자료 **목록**을 비교해 `근거 미확인` 거래를 빠짐없이 표시하는 것이다.

## 2. 이번 버전의 범위

교육용 **가상 CSV 두 파일**을 입력받아 로컬에서 실행되는 작은 대조 도구를 만든다. 프로그래밍 경험이 없는 담당자도 따라 할 수 있도록 실행 방법을 설명한다. 인터넷 연결, 외부 AI 호출, 계정, 실제 업무시스템 접근 및 은행 거래 기능은 요구하지 않는다.

| 입력 파일 | 필수 열 | 의미 |
| --- | --- | --- |
| 거래 목록 CSV | `거래번호`, `거래일`, `입출금 구분`, `금액`, `적요` | 업무시스템 거래내역을 흉내 낸 가상 목록 |
| 근거자료 목록 CSV | `자료번호`, `연결 거래번호`, `문서일`, `금액`, `자료유형` | 엑셀·PDF·공문 등의 **원문이 아닌**, 사람이 정리한 가상 자료 목록 |

**기본 연결 기준은 거래번호 = 연결 거래번호이다.** 금액이나 날짜가 비슷하다는 이유만으로 자료를 임의로 연결하지 않는다. CSV 열 순서가 바뀌어도 열 이름으로 읽어야 한다. 금액은 정확히 비교하고, 빈 값·잘못된 형식은 임의 보정 없이 검토 대상으로 표시한다. 문서일과 거래일이 반드시 같아야 하는지는 정해진 규칙이 없으므로 동일성 판정에 사용하지 않는다.

## 3. 기대 출력과 판정 규칙

`거래별_대조결과.csv` 한 개를 생성한다. **입력 거래의 각 행은 결과에 정확히 한 행씩**, 원래 순서대로 나타나야 한다. 최소 출력 열은 `거래번호`, `일자`, `입출금 구분`, `금액`, `근거자료 번호`, `상태`, `확인 사유`이다. 원래 거래의 금액·일자 등은 수정하지 않는다.

상태는 다음 네 값만 사용한다.

1. `일치`: 유일한 거래번호에 유일한 근거자료가 연결되고 금액도 같은 경우. 이것은 **목록상 일치**일 뿐 서류의 진위나 거래의 적법성 인정이 아니다.
2. `근거 미확인`: 해당 거래번호에 연결된 근거자료가 없는 경우. 누락된 자료를 추정해서 채우지 않는다.
3. `금액 불일치`: 거래번호는 명확히 연결되지만 두 금액이 다른 경우.
4. `중복·검토 필요`: 동일 거래번호 중복, 한 거래에 여러 근거자료 연결, 거래번호 누락, 필수 열 또는 금액의 잘못된 형식 등으로 안전하게 판정할 수 없는 경우. `확인 사유`에 구체적인 이유를 적는다.

판정이 충돌하면 **중복·형식 오류 → 근거 없음 → 금액 불일치 → 일치** 순으로 보수적으로 처리한다. 이 우선순위와 한 거래에 복수 자료가 있는 경우의 처리 방식을 코드·사용법에 명시한다. 입력에 없는 근거자료나 거래정보를 만들어내지 않는다. 연결 거래번호가 비어 있는 자료를 금액·일자로 자동 배정하지 않는다.

## 4. 사용자 작업 흐름

1. 담당자가 가상 거래 CSV와 가상 근거자료 목록 CSV를 지정한다.
2. 도구가 열 이름·값을 검증하고 거래번호 기준으로 대조한다.
3. 결과 CSV에서 `근거 미확인`, `금액 불일치`, `중복·검토 필요` 건과 그 사유를 확인한다.
4. 실제 업무에 적용하는 경우에도 담당자가 원본 증빙과 관계자에게 직접 확인하며, 결재·지급·반환 및 장부 수정은 기존 절차에 따른다.

## 5. 검증해야 할 사례

가상 자료만으로 테스트를 작성하고 결과를 보여 달라.

- 정상: 거래 2건과 각각의 근거자료 2건에서 번호·금액이 일치하면 모두 `일치`.
- 누락: 거래 1건에 연결할 자료가 없으면 `근거 미확인`; 다른 자료를 임의 연결하지 않음.
- 불일치: 연결 거래번호는 맞지만 금액이 다르면 `금액 불일치`.
- 모호함: 빈 연결 거래번호, 거래번호 중복, 복수 자료 연결, 금액 형식 오류 등이 있어도 거래 행이 사라지거나 `일치`로 잘못 확정되지 않음.
- 열 순서 변경: 두 CSV의 열 순서를 바꿔도 이름 기준으로 동일하게 처리됨.
- 빈 입력 또는 필수 열 누락: 조용히 성공한 척하지 말고 이해할 수 있는 오류나 검토 메시지를 제공함.

합격 기준은 **입력 거래 누락 0건, 근거 없는 거래의 `일치` 판정 0건, 금액 불일치 누락 0건, 원본값 변경 0건**이다. 실제 절감 시간이나 정확도 향상은 아직 측정되지 않았으므로 수치를 만들어내지 않는다.

## 6. 보안·운영 제한

- **지금은 교육용 가상자료만** 사용한다. 실제 거래내역, 내부 공문·원문, 개인정보, 계정정보를 외부 AI나 외부 서버로 보내지 않는다.
- 실제 시스템에서 거래내역을 추출할 수 있는지, 자료마다 거래번호가 연결되는지, 프로그램 설치·반입·내부망 사용이 허용되는지는 아직 확인되지 않았다. 승인받은 것으로 가정하지 않는다.
- 우선 로컬에서만 작동하게 하고 입력 파일은 읽기 전용으로 다룬다. 실제 시스템 연결, PDF·공문 원문 인식, 자동 자료 추적·보완 요청, 결재·지급·반환, 군인복지기금 및 국가채권 기능은 **이번 범위 밖**이다.
- 실제 근거자료가 없는 거래는 도구가 원인을 스스로 찾을 수 없으므로 `근거 미확인`으로 남기고 담당자의 확인을 기다린다.

## 7. 구현을 맡은 AI에게 요청하는 산출물

위 범위의 **로컬 실행용 Python 시제품**을 만들고, 전체 코드, 파일명, 실행 명령, 가상 입력 CSV 예시, 예상 출력 예시, 자동 테스트와 실행 결과를 제공하라. 가능하면 기본 라이브러리만 사용하고, 추가 패키지가 필요하다면 이유와 설치 방법을 설명하라. 코드를 실제 실행하지 못했다면 테스트가 통과했다고 주장하지 말고 미실행이라고 명시하라. 기능을 늘리기 전에 누락·불일치·중복 사례를 먼저 통과시켜라.

### 추후 확인할 사항(지금 임의로 확정하지 말 것)

- 실제 시스템의 승인된 내역 추출 방식 및 열 이름
- 거래번호가 각 근거자료에 실제로 존재하는지와 복수 증빙 처리 규칙
- 거래일과 문서일의 관계, 금액의 단위 및 입금·출금 표기 방식
- 기관의 프로그램·AI 사용 승인, 자료 접근 권한 및 보안 절차

**진행 상태:** 원본 정의서에는 구현·실행·동료 시험이 모두 `미실행`으로 기록되어 있다. 이 문서는 향후 제작용 요구사항이며, 이미 성능을 검증한 앱의 설명이 아니다.
