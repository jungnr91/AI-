# 군인복지기금 집행 건별 근거서류 누락 점검 도구 개발 요청

이 문서는 `정누리_나의_업무문제_정의서_군인복지기금_작성본.docx`의 **첫 과제**를 구현할 AI에게 전달할 요구사항이다. 이전의 세입세출외현금 과제(`problem.md`)와는 **별개의 도구**로 만든다.

## 1. 배경과 해결할 문제

- 사용자는 국군의무사령부 재정과에서 군인복지기금 집행 증빙 확인과 월별·연별 결산을 담당한다.
- 집행 건이 들어오는 거의 매일 집행부서가 제출한 집행의뢰 공문, 영수증, 세금계산서, 산출내역서, 견적서 등 다양한 근거서류를 하나씩 확인한다.
- 집행 건에 필요한 서류가 빠졌는지, 내용에 오류가 있는지 찾는 일이 가장 오래 걸린다. 다만 이번 첫 기능은 **서류 유형의 제출 여부**만 점검한다. 서류 내용 검증과 월·연 결산까지 한 번에 자동화하지 않는다.
- 어떤 서류가 필수인지는 집행유형과 내부 기준에 따라 달라질 수 있다. **실제 필수서류 기준은 아직 제공되지 않았으므로 AI가 규칙을 만들어서는 안 된다.**

## 2. 이번 버전의 입력과 범위

교육용 **가상 CSV 세 파일**을 입력받아 로컬에서 작동하는 작은 프로그램을 만든다. 세 번째 파일은 담당자가 확인한 필수서류 유형 목록을 나타내는 **실습용 기준표**이며, 제도상 실제 요건이라고 주장하지 않는다.

| 입력 파일 | 필수 열 | 역할 |
| --- | --- | --- |
| 집행 건 목록 CSV | `건번호`, `집행유형`, `집행일`, `금액` | 점검할 가상 집행 건 |
| 제출서류 목록 CSV | `건번호`, `서류유형`, `서류번호`, `기재금액` | 건별로 제출됐다고 기록한 가상 서류의 **목록** |
| 유형별 필수서류 목록 CSV | `집행유형`, `필수서류유형` | 담당자가 별도로 정한, 실습용 유형별 필수 기준 |

`건번호`로 집행 건과 서류 목록을 연결하고, 해당 건의 `집행유형`으로 기준표를 찾는다. 제출된 `서류유형` 집합에서 필수서류 유형 중 빠진 항목을 찾는다. CSV의 열 **순서**가 달라도 열 이름으로 읽는다. 영수증·PDF·공문 **원문을 자동 인식하거나 읽는 기능은 포함하지 않는다.** `기재금액`은 입력 형식에 남겨 두되 첫 기능에서 금액 대조에 사용하지 않는다.

## 3. 기대 출력과 보수적인 판정

`집행건별_누락서류_점검표.csv` 한 개를 만든다. 입력 집행 건의 **각 행을 누락하지 않고 원래 순서대로** 출력한다. 최소 열: `건번호`, `집행유형`, `제출서류 목록`, `필수서류 대비 누락 목록`, `상태`, `확인 사유`.

상태는 정의서의 다음 세 값을 사용한다.

1. `누락 없음`: 해당 집행유형에 적용할 **명시된 필수서류 목록이 있고**, 그 목록의 모든 서류유형이 제출서류 목록에 있으며 식별이 모호하지 않은 경우. **서류 존재 여부만** 뜻한다.
2. `누락`: 명시된 필수서류 목록에서 제출되지 않은 유형이 한 개 이상 확인된 경우. 누락 목록에 해당 유형을 적는다.
3. `기준 미정·검토 필요`: 해당 집행유형의 기준이 없거나, 건번호·서류유형 등이 비어 있거나, 같은 건번호의 집행 건·서류행이 중복되어 확정하기 어려운 경우. 반드시 `확인 사유`에 `기준 없음`, `중복 서류`, `식별정보 누락` 등 실제 원인을 구분해 적는다. 중복이라는 이유로 제출되지 않은 서류를 제출된 것으로 꾸며서는 안 된다.

필수 기준에 없는 집행유형은 제출서류가 있더라도 `누락 없음`으로 추정하지 않는다. 기준표의 특정 집행유형에 필수 항목이 **0개인 경우**도, 명시적 허용 규칙이 따로 확인되지 않았으므로 `기준 미정·검토 필요`로 둔다. 중복·누락 등 판단이 충돌하면 안전하게 검토 대상으로 남기고 이유에 발견 사항을 모두 기록한다. 입력 원본값을 수정하거나 존재하지 않는 서류를 만들어내지 않는다.

## 4. 사용자 작업 흐름

1. 담당자가 가상 집행 건 목록, 가상 제출서류 목록, 담당자 확인을 거친 가상 필수서류 기준표를 준비한다.
2. 도구가 열 이름·건번호·집행유형을 확인하고 유형별 필수 목록과 제출 목록을 대조한다.
3. 담당자가 결과 CSV에서 `누락` 또는 `기준 미정·검토 필요` 건의 근거와 사유를 확인한다.
4. 실제 업무에서는 원문과 내부 기준을 담당자가 직접 확인하고 보완 요청 및 결재·집행 판단을 기존 절차에 따라 수행한다.

## 5. 테스트와 합격 기준

아래 시험을 **실제 가상 CSV와 자동 테스트**로 재현한다.

- 정상: 기준표의 필수서류 유형이 모두 해당 건의 제출서류 목록에 있으면 `누락 없음`.
- 누락: 필수서류 유형 하나가 빠지면 `누락`이며 정확히 그 유형이 누락 목록에 나타남.
- 기준 없음: 집행유형이 기준표에 없으면 `기준 미정·검토 필요`이며 자동 적합 판정 금지.
- 모호함: 같은 건번호의 서류행 중복, 빈 건번호 또는 빈 서류유형이 있으면 건을 누락하거나 자동으로 `누락 없음`으로 확정하지 않음.
- 열 순서 변경: 세 파일의 열 순서를 바꾸어도 이름 기준으로 동일하게 처리됨.
- 빈 파일·필수 열 누락: 조용히 통과시키지 말고 담당자가 이해할 수 있는 오류나 검토 사유를 제공함.

**합격 기준:** 입력 집행 건 누락 0건, 제출되지 않은 필수서류를 `누락 없음`으로 표시한 건 0건, 기준 없는 유형을 적합하다고 판정한 건 0건, 원본값 임의 변경 0건. 실제 절감 시간과 정확도는 아직 측정되지 않았으므로 수치를 만들지 않는다.

## 6. 보안·제외 범위

- 지금은 **가상자료만** 다룬다. 실제 영수증·세금계산서·공문 원문, 개인정보, 기관 내부 자료나 계정정보를 외부 AI에 입력하거나 외부 서버로 보내지 않는다.
- 실제 집행유형별 필수서류 기준표, 제출 문서의 식별 방식, 기관의 설치·반입·내부망 사용 및 AI 활용 승인은 아직 확인되지 않았다. 실제 업무 적용이 허용된 것으로 가정하지 않는다.
- 서류의 내용·진위·금액·날짜 오류, 지출의 적법성, 결재·지급, 월별·연별 결산, 원문 자동 판독·OCR은 **이번 기능 밖**이다. `누락 없음`을 최종 검토 완료 또는 집행 승인으로 표시하지 않는다.
- 입력 파일은 읽기 전용으로 다루고, 결과는 로컬에만 저장한다. 기관 시스템 연동이나 자동 보완 요청을 구현하지 않는다.

## 7. 구현을 맡은 AI에게 요청하는 산출물

위 범위의 **로컬 실행용 Python 시제품**을 만들고 전체 코드, 파일명, 실행 명령, 가상 입력 CSV 세 개, 예상 출력 예시, 자동 테스트 및 **실제 실행한 경우에만** 그 결과를 제공하라. 프로그래밍 경험이 없는 담당자가 따라 할 수 있도록 안내하라. 가능하면 표준 라이브러리만 사용하고, 추가 패키지가 필요하다면 이유와 설치 방법을 설명하라. 우선 `누락 없음`·`누락`·`기준 미정·검토 필요` 판정부터 시험하고 기능을 확대하지 마라.

### 추후 확인할 사항(임의로 확정하지 말 것)

- 실제 집행유형과 유형별 필수서류 기준의 근거·관리 주체
- 하나의 집행 건에 같은 유형의 서류가 여러 개 필요한지 및 중복 서류 처리 기준
- 제출서류별 건번호 식별 방법, 실제 사용 파일 형식과 승인된 자료 추출 방법
- 자료 접근 권한, 보안 등급, 프로그램·AI 사용 및 내부망 반입 승인 절차

**진행 상태:** 원본 정의서에는 구현·테스트·동료 사용 결과가 모두 `미실행`으로 기록되어 있다. 이 문서는 제작 요청용 요구사항이며 이미 검증된 앱의 설명이 아니다.
